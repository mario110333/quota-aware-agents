# Bounded Astra consultation

Read for a concrete Astra second opinion. The main retains the goal, implementation, integration and evidence-based acceptance; this preference grants no main-model changes, new external authority or enforced spending cap.

## Value and package

Use a bounded consultation for an important unresolved reasoning/architecture/evidence question after reasonable initial analysis, or an independent argument before a consequential decision. Ordinary complexity, file count, routine review or one failed test is insufficient. Distinguish missing facts, permissions/environment, tool limits and actual reasoning difficulty first; obtain needed originals rather than replace observations with opinions.

An automatic proposal needs material independent value and different necessary main work. If everything hinges on this question, normally recommend a main-model switch without changing it yourself. **An explicit request for bounded read-only consultation may proceed without parallel work** when tools and permissions allow it; no invented waiting work or duplicate approval/window.

Normally use supported `gpt-6-astra` / `xhigh` for one read-only package and one conclusion, with at most one necessary brief clarification within the same question/scope. Provide the concrete question, critical constraints, accessible originals, facts versus assumptions, current proposal/disagreement and a discriminating check. Ask for recommendation, counterexamples, uncertainty and minimum verification or inability to conclude. Do not grant product/shared-record writes, installation/publication or recursive delegation.

Advance unaffected work and keep disputed consequential actions pending verification. Test the answer against originals; it is neither authority nor independent evidence merely because another model repeats it. A new core question, extra investigation, another instance or deeper discussion requires a new value/scope check and, for automatic proposals, notice. One package can involve several model requests; it is not a fixed usage cap.

## Automatic notice and the 30-second window

Apply only to automatic Astra proposals unless the user expands it. Silence, a selected option and an unclicked button are not approval. Default execution after silence requires **prior explicit human authorization** within this scope; loading/installing the public skill is not consent. Preserve applicable prohibitions and explicit-approval requirements. Across conversations use trusted authorization records, not assumed shared memory. Host approvals still apply.

Deliver a compact interactive notice through an available asynchronous question tool such as `request_user_input_async`. Offer consult, skip and explain/adjust plus free text. Name the concrete question/value, supported model/effort and read-only scope, different necessary main work, and the preauthorized 30-second default. Include relevant speed/control limits only when needed. Bind it to the current task and plan revision; a lightweight ID suffices. No money estimate, database or separate workflow record is required.

If delivery fails or interactive notice is unavailable, no unanswered timer/default dispatch begins; continue suitable work and state the limit. A direct bounded consultation request already authorizes dispatch when ready, without this notice/wait. Start the automatic window only after successful delivery and measure real elapsed time while advancing useful work.

## Feedback and changes

- Current-plan explicit approval may release early; refusal cancels. Do not rename/re-notify to bypass it. A task-wide ban persists until lifted; a one-time refusal is not a permanent ban.
- A question, explanation request or adjustment pauses default execution. Answer/revise first; a material revision gets a new notice/window. Questions are not silence or automatic consent.
- Immediately before dispatch, recheck latest replies, active task, necessity, permissions and the valid default/notice. After at least 30 seconds with no reply, record **preauthorized default execution**, never human approval. A late reply received before dispatch governs.
- Bind approval to its revision. Material goal/scope, Astra model/effort, instance count, investigation authority or explicit budget changes invalidate the old plan. Do not transplant an ambiguous old reply; clarify it. Main-model/goal changes require reassessing whether consultation is still useful.
- After dispatch, cancellation stops further consultation and interrupts the worker where supported. Preserve valid results and actual call evidence; consumed usage cannot be reversed. Resolve any possible continuing effects before affected ownership transfer under [execution evidence](execution-evidence.md).
- A plan already following latest main speed need not reopen for ordinary toggles; use [speed following](speed-following.md). Breaching an explicit speed/budget constraint requires revision. Unsupported controls remain unsupported; messages cannot apply speed.
- Handle the window only in the active task. No background timer, automation, new chat or later autonomous release. Finished/replaced/interrupted tasks do not dispatch on expiry; resumption needs a fresh validity check and notice/window if the old one is no longer applicable.

End once the decision and necessary verification are clear. Missing facts require bounded collection; inconclusive answers remain explicit limits. Disagreement calls for a falsifiable distinction, not a standing discussion or approval chain.
