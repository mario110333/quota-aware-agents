# Model routing

Routing baseline: 2026-10-08. Read for a worthwhile worker package or an explicitly requested bounded Astra consultation. These are starting choices, not guarantees of quality, savings or tool availability. Keep the main model/effort under the user's control.

| Work | Starting route | Selection rule |
|---|---|---|
| Small, ordinary, or difficult coupled work | Current main directly | Complexity, steps, and main xhigh alone do not justify a worker. |
| Worthwhile independent complete execution/review/analysis package | `gpt-6.1-sol`, normally verified supported Sol main effort | Useful different necessary main work; same-model workers have no model-rate advantage. Under Astra main, complex independent execution normally uses Sol/xhigh. |
| Deliberately reduced Sol effort | `gpt-6.1-sol` / `high`, exception | Stable contracts, straightforward acceptance, necessary parallel work, and a concrete adequacy/efficiency reason. |
| Mechanical batch | Tools/scripts | Counts, hashes, exact extraction and reference checks need no model worker. |
| Sufficient explicit-rule, verifiable semantic batch | `gpt-6-luna` / `max` | One complete batch; ambiguity, acceptance or repair must not erase its benefit. Do not silently lower max. |
| Concrete critical reasoning/architecture/evidence/data-protection question | `gpt-6-astra`, normally `xhigh`, read-only | Enough originals and reasonable initial analysis; use [Astra consultation](astra-consultation.md). An independent consequential decision analysis need not wait for repeated failures. |

## Current families and availability

Default worker IDs are exactly `gpt-6.1-sol`, `gpt-6-luna` and `gpt-6-astra`. **Do not select `gpt-6-sol` or `gpt-5.6-luna` as availability/regression fallbacks.** Listing a model in the tool is not authorization to use it. Apply this to spawning, replacement, inheritance and continuation of an old worker. A specific explicit user choice for a package overrides the default; historical identification/accounting of old IDs is still valid.

If the preferred combination is unavailable, continue directly or choose another allowed, supported and adequate route after the same value/scope check. Do not silently substitute an old family, lower a requested effort, repeatedly probe IDs, or change main/global settings. Unknown main identity/effort permits task-appropriate judgment; for complex Sol work the supported fallback is normally `gpt-6.1-sol` / `xhigh`, disclosed briefly, or direct work. It does not establish a guessed identity or savings.

Use active-turn-bound host metadata when needed; otherwise [optional identification](model-identification.md) applies only if the result changes routing. Defaults, latency, old turns and a worker's identity do not identify the main. Another known main model needs its own capability/risk assessment. A legacy main does not authorize legacy worker inheritance.

## Effort, continuation and tool mechanics

Under Sol main, normally preserve verified current supported effort via real inheritance or supported arguments. User-selected main high naturally permits high workers. Reducing a higher effort to Sol/high additionally needs a substantial independent package and the specific adequacy/efficiency reason above; known scope or lower nominal cost alone is insufficient. Use relevant acceptance history when available, without a mandatory paid pilot or extra reviewer. Significant main rework calls for a better boundary or direct work.

At dispatch/reuse after a main model/effort change, reassess remaining value and actual worker suitability; preserve accepted work and applicable checks. Do not continue an old-family worker under the default merely because it is idle or has context. Stop obsolete work and safely transfer affected ownership before replacing it. Model routing governs chosen task workers, not the host's internal services or billing labels.

Read the live schema: current `spawn_agent` overrides require `fork_turns="none"` or limited history, not `"all"`; `send_message`/`followup_task` cannot change model/effort. If inheritance would produce a disallowed or inadequate configuration, use explicit supported arguments or remain direct. Executing requests cannot be reconfigured retroactively. Speed has a separate capability gate and [latest-setting protocol](speed-following.md).

Normally start with one qualifying worker; add only a distinct independent line within tool limits. Use subagent tools for subtasks, not user-owned chats. Avoid recursive delegation and busy polling. Escalate for a specific reasoning problem after checking facts/tools/environment, not retry count. Further effort reductions remain evidence-based calibration candidates, not defaults or proof of faster, cheaper or equivalent results.
