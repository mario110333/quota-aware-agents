# Choosing a worker model and effort

Use the live tool's supported models, effort levels, history modes and override permissions. Apply explicit choices first. The user can explicitly request a retired model for a particular assignment if supported.

Use these judgments where the choice matters. The main can work directly in any of these cases.

| Work | What changes the choice |
|---|---|
| Mechanical extraction, counting or comparison | A script can apply an exact rule and show discrepancies in one pass. |
| Repeated semantic judgments with stable criteria | A faster or lighter worker can handle an entire batch if errors are visible and economical to correct. Give it an ambiguous example when one defines the boundary. |
| Implementation or synthesis with several dependencies | Prefer a worker that can carry the integration through acceptance. A handoff that forces the main to reconstruct much of the solution has little value. |
| A consequential decision with plausible competing explanations | Stronger reasoning or an independent read can be worth extra time and tokens. Supply primary evidence and the decision at stake. |

Choose effort for the remaining judgment and cost of repair. For version order and stability, use reliable host labels or known release information. Preview labels, list position and ambiguous names alone do not establish the latest stable version. When the ordering is unclear, pick a supported, suitable option within the user's constraints and leave its ranking unknown. Mention a material fallback briefly. Preserve an existing suitable worker when restarting would discard useful progress.

If full history requires inheritance, use a compatible fresh context and supply the necessary originals for an allowed override. Messages carry task instructions; runtime changes require a supported control.

If the host leaves the inherited model unclear and a model constraint applies, choose an explicitly supported and permitted worker that satisfies it, or handle the work directly. For a user request to identify the active main model, see [model identification](model-identification.md).
