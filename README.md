# quota-aware-agents — Codex / OpenAI 模型分工 Skill

**简体中文** · [English](README.en.md)

### 让每一次代理分工，都有值得承担的工作。

[安装](#安装) · [使用示例](#使用示例) · [默认路由](#默认路由) · [常见问题](#常见问题) · [版本发布](https://github.com/mario110333/quota-aware-agents/releases)

用于 Codex 的按需分工 Skill。先判断是否值得分工，再按需要识别当前主模型和选择子代理；总完成成本包括上下文、协调、通知等待、验收和返工。作者：**malioe**；版本：**1.3.0**。

适用于有清楚边界的实现、分析、翻译和批量审查。简单问答、小修改和确定性操作直接处理；只有主代理能同时推进有用工作时，才交给代理一个完整工作包。在阶段变化、执行者完成或出现关键新证据后重新判断。

## 适用范围

面向 **Codex 中的 OpenAI 模型**（如 GPT-6.1 Sol、GPT-6 Astra、GPT-6 Luna），配合当前会话可用的代理工具工作。它是工作指引，不是独立运行的代理框架，也不解锁模型权限。其他使用 OpenAI 模型的环境，需要适配工具接口、权限、模型可用性和用量采集方式后使用。

## 它能做什么

| 能力 | 实际做法 |
| --- | --- |
| 判断是否值得分工 | 将任务说明、代理执行、协调、验收与预计返工一起纳入成本 |
| 适配当前主模型 | 路由需要时核对当前会话与轮次的模型信息，按 Astra、Sol、其他或未知模型选择策略 |
| 跟随主代理速度 | 每次派发与续用前刷新主代理速度；反复切换时按版本确认，区分同步要求与已应用结果 |
| 按任务选择模型 | 根据歧义、失败代价、原始资料依赖和可验证程度选择模型与推理强度 |
| 减少碎片化交接 | 将调查、实现、普通调试、必要验证和相关记录作为完整工作包交付 |
| 控制上下文与冲突 | 使用精简任务卡，明确原始资料、文件归属和共享资源负责人 |
| 保留整体验收责任 | 主代理核对原始要求与关键边界，区分已实现、已验证和未验证的内容 |

共享接口或需求尚未稳定时，先完成并验证一个有代表性的端到端流程，再扩展并行工作。组件分别完成，不代表整体已经验收。

## 1.3.0 更新

- Sol 主代理默认直接完成、初始子代理数为零；多步骤、多文件或主代理使用 xhigh 不能单独成为分工理由。
- 只有完整独立工作包、主代理有必要的并行工作且协作收益明确时才派发。避免重复调查、重做实现和固定多轮复审；阶段结束重新判断剩余工作。
- 必要的 Sol 子代理通常沿用 Sol 主代理已核实的推理强度；Sol/high 保留为有明确充分理由的例外，不再自动从 xhigh 降档。
- 机械批次优先脚本；足够大、规则明确且容易验收的语义批次仍保留 Luna/max。极难但耦合的问题由主 Sol 集中处理。
- Astra 限于具体关键问题的只读第二意见。自动提出时通知用户并给 30 秒反馈窗口；未回应执行须有事先明确授权，提问/调整则暂停。主动点名本次咨询无需重复审批。
- 保留 1.2.1 的速度跟随和来回切换版本规则；速度、推理强度及咨询授权分别管理。没有真实控制时不承诺已有子代理即时热更新。

详细边界见[模型路由](quota-aware-agents/references/model-routing.md)与 [Astra 咨询](quota-aware-agents/references/astra-consultation.md)。规则没有硬费用上限，也不创建后台计时器或自动化。

## 1.2.1 更新

- 子代理速度跟随主代理当前选择，替换固定 Standard；速度、模型与推理强度分别处理。
- 每次派发、续用、设置操作前重新核对速度，观察到切换时立即作废旧确认；不把本轮首次读到的速度缓存到整轮结束。
- 通过递增设置版本处理来回切换及迟到回执；保留有效成果，不因每次切换重复派发整个工作包。
- 明确真实速度控制、仅创建时继承、运行中更新与不可设置／不可核实的边界。任务卡、消息和规则审查不能证明执行速度已切换。

详见[速度跟随规则](quota-aware-agents/references/speed-following.md)。Skill 没有后台监听器；当前工具未暴露速度控制时，无法保证正在执行的子代理请求即时切换。

## 1.2.0 更新

- 将 1.1.0 已有的主模型分工原则补成可靠识别流程：优先当前宿主元数据，必要时用只读辅助脚本核对会话与活动轮次；识别失败采用通用策略。
- 补齐其他及未知主模型的分支。切换模型后重评剩余工作，保留成果、合适的执行者与有效验收。
- 按需处理共享运行资源和实验观察，区分有效阴性与无结论；失败先诊断原因，再调整。
- 统计支持开始时间、多个显式根及来源分组，期间量与生命周期累计分别诊断；未知费用仍为未知。

完整分包、脚本优先和通过后停止继续保留；1.2.0 的固定 Standard 在 1.2.1 中已替换为跟随主代理当前速度。1.3.0 进一步取消 Sol/high 默认路由。升级不承诺固定节省比例。

## 主模型自适应

| 当前主模型 | 默认分工判断 |
| --- | --- |
| Astra | 主方保留重大取舍和关键判断；值得并行的完整包可交给 Sol/xhigh，high 仅作有理由的例外 |
| 6.1 Sol | 默认零子代理，直接承担常规实现、难且耦合的问题与整合；真正独立并行才考虑子代理 |
| 旧 Sol、Luna 或其他型号 | 按确切型号的能力证据、当前工具与任务风险判断，不统一归为 Sol |
| 未知或未映射型号 | 继续通用分工判断，不猜模型，也不因识别失败阻断已授权工作 |

自动适配由 Skill 指引当前代理执行；已有可靠信息时直接复用，无可靠信息时按环境能力选择辅助脚本或通用策略。它没有常驻后台监听，也不改变主对话模型或全局设置。详见[模型路由](quota-aware-agents/references/model-routing.md)。

## 默认路由

| 工作 | 起点 |
| --- | --- |
| 简单工作、普通实现、相互依赖的难题 | 主代理直接完成，不自动改变用户主模型/档位 |
| 真正值得并行的独立 Sol 完整包 | Sol 主代理下通常沿用已核实的主代理推理强度；明确的降档理由才考虑 high |
| 大量机械处理 | 确定性工具/脚本 |
| 足够大、明确规则、容易验收的语义批次 | 必要时 Luna/max，一个完整批次，并要求主代理有实际并行工作 |
| 关键难题或重大决策的第二意见 | Astra/xhigh，具体只读咨询，按通知与授权规则执行 |
| 已有 GPT-6 Sol 工作流 | 优先迁至 GPT-6.1 Sol，并核对受影响的验收结果 |

以上是 **2026-10-07** 的工作流策略，不是模型成功或节省保证。6.1 Sol 不可用时，值得分工的包可回退到工具支持的 `gpt-6-sol` / `xhigh`，或直接完成。high 与速度模式分别选择，不能用降档来合理化多余分工。

子代理速度跟随主代理**当前选择的 Standard / Fast / Ultrafast**，推理强度与速度模式独立。每次派发或续用前刷新，来回切换时拒绝旧版本确认。没有真实设置接口或速度继承证据时，明确记录未核实，不能把通知子代理当作执行速度变更。详见[速度跟随规则](quota-aware-agents/references/speed-following.md)；模型选择、回退与校准见[模型路由](quota-aware-agents/references/model-routing.md)。

模型与推理强度是否可用，以账号、当前工具和权限为准。Skill 不授予代理额外权限，不自动切换主对话模型或全局配置；工具没有速度选项时，也不能据此声称已经更改速度模式。

自动 Astra 通知的 30 秒从交互通知成功送达开始。提前同意可以提前派发，拒绝取消，提问/调整暂停；没有预授权、通知失败或任务已结束就不自动调用。旧通知不能批准新问题，迟到取消会停止后续咨询，不能撤回已消耗用量。普通 Sol/Luna 分工不自动增加此窗口；用户可要求本任务必须明确同意。详见 [Astra 咨询规则](quota-aware-agents/references/astra-consultation.md)。

## 安装

可以向 Codex 发送下面的安装请求；是否能自动安装取决于当前可用的 `skill-installer` 与权限：

```text
请使用 $skill-installer 从 https://github.com/mario110333/quota-aware-agents/tree/main/quota-aware-agents 安装这个 Skill。
```

Windows 用户也可[下载最新仓库 ZIP](https://github.com/mario110333/quota-aware-agents/archive/refs/heads/main.zip)，解压后在包含 `Install.ps1` 的目录运行 `./Install.ps1`。脚本按 [checksums.json](checksums.json) 校验完整 Skill 文件清单，无需管理员权限；已有同名目录时停止，不覆盖旧版。

Windows / macOS / Linux 均可手动将内层 `quota-aware-agents` 文件夹整体复制到 `~/.agents/skills/`，最终入口为 `~/.agents/skills/quota-aware-agents/SKILL.md`。更新前先备份并移走旧目录，避免混合版本；如果 Skill 未显示，重启 Codex。完整操作见[中文安装说明](安装说明.md)或 [English installation guide](INSTALL.en.md)。

安装后可以发送：

```text
请使用 $quota-aware-agents 处理这个任务：……
```

Skill 允许按任务自动调用，但调用后仍需判断是否值得分工。它不要求每次请求都派出代理。

## 使用示例

**实现功能并完成必要验证：**

```text
请使用 $quota-aware-agents 完成这个功能：……
先判断哪些工作可独立交付，再选择模型和分工；由主代理整合并验收。
```

**按明确规则审查一批文件：**

```text
请使用 $quota-aware-agents 按以下规则审查这些文件：……
能用脚本确定的检查先用脚本；有歧义的内容保留原文和判断依据。
```

**只评估方案，暂不执行：**

```text
请使用 $quota-aware-agents 为这个任务评估分工方案：……
说明直接完成和委派的取舍。本次只给出方案，不启动代理或修改文件。
```

## 工作流程

1. **判断**：确认质量要求，先比较直接完成与委派的总成本；只有策略选择需要时才识别主模型。
2. **分包**：写清交付结果、关键约束、原始资料、文件归属、验收要求与输出语言。
3. **执行**：代理负责完整工作包；主代理推进有用的并行工作并处理跨工作包决策。
4. **验收**：按原始需求核对结果与证据，针对缺口修正，通过后停止重复检查。

Sol 默认零子代理；确定分工后通常先一个完整包，额外工作独立且有用时才增加，不递归委派。在阶段变化、执行者完成或关键新证据出现后重新判断，剩余整合通常直接完成。

## 费用参考与可选统计

[费用与用量说明](quota-aware-agents/references/cost-model.md)中的费用快照日期是 **2026-09-30**，历史费率分别注明日期。它们是带日期的参考，后续比较应核实适用费率；API 金额、Codex credits、实际收费和订阅用量不能混算。本 Skill 不承诺固定节省百分比，也不把模型价格差直接当作任务节省。

使用指引本身不要求 Node.js。可选的[模型识别辅助脚本](quota-aware-agents/scripts/resolve-main-model.mjs)与[本地统计脚本](quota-aware-agents/scripts/summarize-usage.mjs)使用支持 `node:sqlite` 只读模式的 Node.js，验证环境为 Node.js 24.21.0。识别辅助脚本只在缺可靠宿主信息且本地适配可用时需要；统计仅在复盘需要时运行。先用 `node <脚本路径> --help` 查看参数。

统计的 `--since` 排除开始时刻、`--cutoff` 包含截止时刻，重复 `--thread` 选入多个根；共同后代只计一次。主对话、主动子任务、自动审批与未知来源分别报告，不自动扫描或归入全部账号活动。

脚本只读读取本机 Codex 数据库与日志，在指定的新目录写入统计结果，默认输出摘要，不上传数据。输出可能含本机路径与会话标识，公开分享前请检查；仓库不包含作者的会话、账号配置、凭据或旧用量数据。内部日志格式变化或记录缺失会使统计不完整，结果不能当作实际账单、订阅额度或已测得的节省。

## 常见问题

**它会为每个请求启动代理吗？**  
不会。只有工作边界清楚、主代理有有用的并行工作，且预计总成本合适时才委派。

**它会自动切换主对话模型、购买额度或开启主代理加速吗？**
不会。它提供工作规则，不改变主对话模型、主代理速度、全局配置或权限，也不授予额外模型访问权。子代理按用户已选择的主代理速度跟随，具体能否应用和核实取决于真实工具。

**主代理来回切换速度，已有子代理会立即切换吗？**
新版要求及时刷新并按最新版本同步，旧任务卡和迟到确认不能覆盖新选择。能否对已运行的子代理热更新由宿主接口决定；工具没有控制或反馈时，Skill 无法保证即时切换，也不会声称已经同步。

**我的工具没有表中的模型怎么办？**  
按照当前工具支持的组合选择适合的回退，或直接完成任务。官方发布、账号界面与代理工具的可用模型并不必然一致。

**安装后没有显示怎么办？**  
确认内层 Skill 文件夹位于正确目录，入口文件名为 `SKILL.md`，避免重复安装到多个搜索目录；必要时重启 Codex，再显式调用 `$quota-aware-agents`。

**切换页面语言会改变 Skill 行为吗？**  
不会。中英文说明介绍同一套规则；实际执行入口和参考文件统一使用英文。可见汇报跟随主对话语言，交付物遵循用户指定语言或项目约定。
